# Деплой сайту 58-ї бригади

Документ для того, хто буде розгортати сайт. Описує все, що потрібно знати: від збірки до підключення власного домену та перевірки після деплою.

---

## 1. Що це за сайт

Статичний односторінковий сайт (лендинг) із формою подачі заявок.

- **Збирається** за допомогою [Vite](https://vite.dev/) — `npm run build` створює папку `dist/`.
- **Бекенду немає.** Жодного сервера, Node.js-рантайму, PHP чи бази даних на хостингу **не потрібно**.
- **Деплой = віддати вміст папки `dist/` будь-якому статичному хостингу** (Cloudflare Pages, Netlify, Vercel, GitHub Pages, звичайний nginx/Apache або шаред-хостинг з FTP).
- **Форма заявок** працює через сервіс [EmailJS](https://www.emailjs.com/) безпосередньо з браузера відвідувача — листи відправляє EmailJS, не сайт.

Розмір готового білду — близько 6 МБ (переважно зображення у форматі WebP).

## 3. Налаштування перед збіркою

### 3.1 Встановлення залежностей

```bash
npm ci        # рекомендовано: ставить точні версії з package-lock.json
# або
npm install
```

### 3.2 Ключі EmailJS

Три ключі EmailJS **передаються окремо від архіву** (в архіві їх немає з міркувань безпеки). Створіть файл `.env` у корені проєкту на основі `.env.example`:

```bash
cp .env.example .env
```

і впишіть отримані значення:

```env
VITE_EMAILJS_PUBLIC_KEY=xxxxxxxxxxxxxxxx
VITE_EMAILJS_SERVICE_ID=service_xxxxxxx
VITE_EMAILJS_TEMPLATE_ID=template_xxxxxxx
```

> ⚠️ **Важливо:** Vite вшиває ці змінні у JavaScript-бандл **на етапі збірки**, а не читає їх під час роботи сайту. Тому `.env` (або змінні оточення в панелі хостингу) мають бути на місці **до** запуску `npm run build`. Якщо збілдити без них — сайт відкриється, але форма заявок не відправлятиме листи, а в консолі браузера буде попередження `EmailJS Public Key не знайдено`.

Де взяти ключі, якщо вони втрачені: панель EmailJS → **Account → General** (Public Key), **Email Services** (Service ID), **Email Templates** (Template ID).

## 4. Збірка

```bash
npm run build
```

Результат — папка `dist/`:

```
dist/
├── index.html
└── assets/          # хешовані JS, CSS та всі зображення
```

Локальна перевірка готового білду (підніме сервер на http://localhost:4173):

```bash
npm run preview
```

Режим розробки (з гарячим перезавантаженням, http://localhost:3000):

```bash
npm run dev
```

> Папку `images/` **не потрібно** завантажувати на хостинг окремо — Vite сам копіює всі використані зображення в `dist/assets/` з хешами в іменах файлів.

## 5. Варіанти деплою

### Варіант А — автоматичний деплой з GitHub ⭐ рекомендовано

Підходить для **Cloudflare Pages**, **Netlify** або **Vercel**. Сайт перезбирається й оновлюється автоматично при кожному `git push` у гілку `main`.

Репозиторій: `https://github.com/delta-58/site-ver-5`

Налаштування в панелі хостингу при створенні проєкту:

| Параметр | Значення |
|---|---|
| Framework preset | `Vite` (або `None`) |
| Build command | `npm run build` |
| Build output / Publish directory | `dist` |
| Node version | `22` |
| Root directory | корінь репозиторію (не змінювати) |

Потім у налаштуваннях проєкту (**Settings → Environment variables**) додати три змінні для оточення Production:

```
VITE_EMAILJS_PUBLIC_KEY
VITE_EMAILJS_SERVICE_ID
VITE_EMAILJS_TEMPLATE_ID
```

> На Cloudflare Pages версію Node задають змінною оточення `NODE_VERSION=22.12.0`.

Після збереження хостинг зробить перший деплой сам і видасть технічну адресу (напр. `site-ver-5.pages.dev` або `*.netlify.app`) — на ній можна все перевірити ще до підключення власного домену.

### Варіант Б — завантаження готового `dist/` вручну

Підходить для Cloudflare Pages (Direct Upload), Netlify Drop, звичайного nginx/Apache або шаред-хостингу з FTP/cPanel.

1. Локально виконати `npm ci` і `npm run build` (з налаштованим `.env` — див. п. 3.2).
2. Завантажити **вміст** папки `dist/` (тобто `index.html` та папку `assets/`) у корінь сайту — **не саму папку `dist`**.

Для nginx достатньо вказати `root` на цю папку:

```nginx
server {
    listen 443 ssl;
    server_name example.com;

    root /var/www/58brigade;   # тут лежать index.html та assets/
    index index.html;

    # Довге кешування хешованих ассетів
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

Ніяких `proxy_pass`, PHP чи SPA-fallback (`try_files ... /index.html`) не потрібно: сайт односторінковий, навігація всередині — через анкори.

### Варіант В — GitHub Pages

Працює, але має дві особливості, які **обов'язково** потрібно врахувати:

1. Якщо сайт буде доступний за адресою з підпапкою (`delta-58.github.io/site-ver-5/`), то в `vite.config.js` потрібно додати `base`:

   ```js
   export default defineConfig({
     base: '/site-ver-5/',
     // ...
   });
   ```

   Без цього всі стилі, скрипти й зображення дадуть 404 (див. п. 8). Якщо ж одразу підключається власний домен у корені — `base` змінювати не потрібно.

2. Потрібен GitHub Actions workflow (`.github/workflows/deploy.yml`), який робить `npm ci`, `npm run build` і публікує `dist/`, а три ключі EmailJS треба додати в **Settings → Secrets and variables → Actions** і передати в крок білду як env.

Якщо немає вагомої причини саме для Pages — простіше взяти Варіант А.

## 6. Підключення власного домену

Кроки однакові для всіх хостингів з Варіанту А:

1. У панелі хостингу: **Custom domains → Add domain**, вписати домен (напр. `example.com` і окремо `www.example.com`).
2. Хостинг покаже, які DNS-записи створити в реєстратора домену. Типово:
   - `www` → **CNAME** на технічну адресу проєкту (`site-ver-5.pages.dev` і т.п.);
   - корінь домену (`@`) → **A**-запис на вказані IP, або **ALIAS/ANAME/CNAME-flattening**, якщо DNS-провайдер це підтримує (у Cloudflare — підтримує).

   > Беріть значення записів саме з панелі свого хостингу — вони різні й змінюються.
3. Дочекатися видачі HTTPS-сертифіката (зазвичай від кількох хвилин до години; видається автоматично й безкоштовно).
4. Увімкнути редірект **HTTP → HTTPS**.
5. Вибрати канонічний варіант адреси — з `www` або без — і налаштувати редірект з другого на нього, щоб не було двох однакових сайтів для пошукових систем.
6. **Після появи домену — додати його в allowlist EmailJS** (див. наступний пункт).

## 7. Чекліст перевірки після деплою

- [ ] **EmailJS allowlist.** Панель EmailJS → **Account → Security** → додати новий домен у список дозволених (Allowed origins / Domain restrictions). **Без цього форма заявок на продакшені не працюватиме** — EmailJS відхилятиме запити з нового домену.
- [ ] **Тестова заявка.** Заповнити й відправити форму на живому сайті, переконатися, що лист реально дійшов на поштову скриньку. Якщо ні — відкрити консоль браузера (F12) і подивитися помилку.
- [ ] **Фонові зображення.** Прокрутити всю сторінку: головний баннер, блоки з перевагами, блок контактів — усі фони мають бути видимі. Якщо фони зникли, а текст є — майже завжди це неправильний `base`/підпапка (п. 8).
- [ ] **Мобільна версія.** Перевірити на телефоні або через DevTools (F12 → device mode): для мобільних є окремі фонові зображення, вони мають відрізнятися від десктопних.
- [ ] **Відео.** Блок з YouTube-відео — ролики мають завантажуватись і відтворюватись.
- [ ] **Зовнішні посилання.** Кнопка «Переглянути актуальні вакансії» (веде на `58ompbr.lobbyx.army`) та іконки соцмереж (Facebook, Instagram, YouTube).
- [ ] **HTTPS.** Сайт відкривається по `https://`, у браузері замок без попереджень, `http://` редіректить на `https://`.

## 8. Відомі обмеження та на що звернути увагу

**Шляхи до ассетів абсолютні.** У збудованому `dist/index.html` і CSS посилання мають вигляд `/assets/...`. Це означає, що сайт має жити **в корені домену**. Для розміщення в підпапці (`example.com/site/`) потрібно задати `base: '/site/'` у `vite.config.js` і перезібрати проєкт.

**Tailwind підключений через Play CDN.** У `index.html` є рядок `<script src="https://cdn.tailwindcss.com?plugins=forms,container-queries"></script>` — це CDN-версія Tailwind, офіційно не призначена для продакшену: стилі залежать від доступності зовнішнього CDN і можливий короткий «стрибок» верстки при першому завантаженні. Сайт працює, але якщо надалі є бажання це покращити — поставити Tailwind локальною залежністю (`npm i -D tailwindcss @tailwindcss/vite`) і прибрати CDN-скрипт.

**Інші зовнішні залежності сторінки** (працюють з CDN, нічого налаштовувати не потрібно, але варто знати, що без доступу до них сайт виглядатиме інакше): Google Fonts (шрифт Work Sans), EmailJS SDK з jsDelivr, YouTube-iframe.

**Ключі `VITE_*` публічні.** Усе, що починається з `VITE_`, попадає у відкритий JavaScript-бандл і видно в коді сторінки. Для публічних ключів EmailJS це нормально й передбачено сервісом, але **справжні секрети** (паролі, API-ключі з правами на запис, токени) так додавати не можна — для них потрібен бекенд або serverless-функція.

**Що не лежить у git:** папка `dist/` і файл `.env` додані до `.gitignore` — у репозиторії їх немає й бути не повинно.

## 9. Як оновлювати сайт надалі

**Якщо налаштовано Варіант А (авто-деплой з GitHub):**

```bash
# внести правки у index.html / styles.css / script.js / images/
npm run dev          # перевірити локально
git add -A
git commit -m "Опис змін"
git push origin main # хостинг сам перезбере й опублікує
```

**Якщо деплой вручну (Варіант Б):**

```bash
npm run build        # зібрати заново
npm run preview      # перевірити локально
# залити вміст dist/ на хостинг, замінивши попередні файли
```

Старі файли в `assets/` краще видаляти при заливці: імена хешовані, тому при кожній збірці вони змінюються й непотрібні накопичуються.

## 10. Що в архіві з проєктом

**Включено:**

```
index.html            # головна (і єдина) сторінка
styles.css            # власні стилі + фонові зображення
script.js             # логіка: меню, анкори, форма заявок (EmailJS)
images/               # усі зображення (WebP) + favicon
vite.config.js        # конфігурація збірки
package.json          # скрипти та залежності
package-lock.json     # зафіксовані версії (потрібен для npm ci)
.nvmrc                # версія Node.js — 22.12.0
.env.example          # шаблон змінних оточення
README.md             # загальний опис проєкту
DEPLOY.md             # цей документ
```

**Свідомо не включено:**

- `node_modules/` — ставиться командою `npm ci`;
- `dist/` — генерується командою `npm run build`;
- `.env` з реальними ключами EmailJS — **три ключі передаються окремо** (див. п. 3.2);
- службові папки редакторів (`.idea/`, `.vscode/`).
